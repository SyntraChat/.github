# Security reporting

Do not post credentials, private message content, exploitable details or signing secrets
in public issues. Use GitHub's private vulnerability reporting on the affected repository
when enabled. Administrators must enable it under Settings → Security before release.
No security contact address or response SLA has been designated yet; do not invent one.

The project is a foundation preview and has no supported stable release. Reports should
include version, OS/WebView runtime, a minimal non-sensitive reproduction and impact.
Coordinate public disclosure with maintainers after a fix. Security fixes require tests
and must not be bypassed to restore service compatibility.
